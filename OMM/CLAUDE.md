# OMM: Old Man Maintenance

A native SwiftUI (iOS 18+, iPhone, portrait) version of the OMM workout web app at steveburlison.com/omm/. The program cycles supersets through upper body, lower body and core muscle groups until all 28 groups are crossed out. The behavior spec is `OMM-App-Specification.md` on the user's Windows desktop. The web app's `index.html` is the reference implementation, and this port follows it exactly unless noted below.

## Layout

- `OMM.xcodeproj` is an Xcode 16 synchronized-folder project (objectVersion 77). Files added under `OMM/` join the app target automatically, so never edit `project.pbxproj` just to add a file.
- `Packages/OMMKit` holds Foundation-only logic plus XCTest:
  - `Catalog` and `Exercises`: the 7 × 4 grid in three sections (upper, lower, core) and 10 exercises per group
  - `ProgramState`: progress, weights, start date and daily sets, plus `lastTrained` (the grid's 7-day fade) and `lifts` (reps per set and a "too heavy" tick). It decodes saves that lack the newer fields.
  - `WorkoutPlan` (cardio minutes come out of the total) and `GroupSelection`
  - `WeightAdvice`: Steve's rule. First set 12+ and last set 9+ → up 5 lb; "too heavy" → down 5 lb; else same.
  - `Cardio`: the cardio list
  - `Stretches`: a library of about 35 stretches and yoga poses (each with body area, groups stretched, standing or floor), two per area for after workouts, `StretchRoutine` (saved routines with a hold time per move) and `StretchPlanner` (the Stretch tab's "For you today": groups trained today or yesterday, plus optionally the groups coming up next, fitted to 5, 10 or 15 minutes, standing moves first)
  - `StretchFigures`: a simple line drawing for every library move, as points on a 100 × 100 grid
  - `HowTo`: looping stick-figure how-to animations (pose blending and elbow/knee math). The drawings are data in `HowToMoves.swift`, generated by `node OMM/tools/howto/generate.js` from `tools/howto/moves.js`; check them first in `tools/howto/preview.html` (serve the folder over http, `?sheet=` shows every key pose). Only Mid chest (10 exercises) is drawn so far; roll out one group at a time. Drawings must be original.
- `OMM/App` has `AppModel`, which owns the state and saves `ProgramState` as JSON in UserDefaults (`program.v1`). Flow: sets → cardio (if on) → weight sheet → stretches (if on) → home.
- `OMM/App/MainTabs` holds the bottom tabs (Workout and Stretch, `AppModel.tab`). A workout, a stretch routine and the completion screen still take the whole screen, outside the tabs.
- `OMM/Workout/WorkoutSession` runs the set-by-set flow, the rest timer (±15 s for this workout only) and cardio. `OMM/Stretch` has the Stretch tab (For You Today, My Routines, By Body Area), the routine editor (saved under `stretchRoutines.v1`, apart from the program so Reset keeps them) and the hold screen used after workouts and from the tab.
- `OMM/Presets`: Quick Log. People save their own presets (`Preset` in OMMKit, saved under `presets.v1`, apart from the program so Reset keeps them); one tap of Log adds a set per exercise to its group, with Undo. `GroupGuess` fills a group in from a typed machine name. Nothing about any one gym is built in.
- `OMM/Support` has the theme, `Countdown` (shared by rest, cardio and stretch holds), the chime (a WAV built in memory) and the notification.
- `Config/Info.plist` is merged into the generated Info.plist.

## Commands

```bash
cd Packages/OMMKit && swift test
xcodebuild -project OMM.xcodeproj -scheme OMM -destination 'generic/platform=iOS Simulator' build
```

If `xcodebuild` complains about the developer directory, ask the user to run `sudo xcode-select -s /Applications/Xcode.app`.

## Rules

- Keep the web app's storage keys and math. Thresholds are 3 / 6 / 12 sets. Rest is `round(minutes × 60 ÷ sets) − 30` seconds. The estimate is remaining sets ÷ average sets per workout day, rounded up.
- "Inner" is two different groups. Their keys are `Inner (Thighs)` and `Inner (Chest)`.
- The rest timer stores an end date and never counts ticks, so it stays right after the app is backgrounded. A local notification covers the locked-phone case. In the foreground the chime and a haptic play instead.
- Swift 5 language mode is deliberate.
- The app is light-mode only (`UIUserInterfaceStyle = Light`) because the design is white cards on a purple gradient.
- Commit, push, or change signing and the bundle ID only when the user asks.

## Differences from the web app

- **Back to Home** asks for confirmation before it throws away the workout.
- The duration slider remembers its last value.
- Version 2 (from App HQ feedback, 2026-11-03): labeled, colored grid sections; recently trained groups fade; adjustable rest with a finish time; reps and a suggested weight; optional cardio; stretching after workouts (on by default) and on its own.
- A local notification fires when rest ends while the app is in the background.
- The home grid opens with one upper, one lower and one core group already picked (`NextGroups` in OMMKit, App HQ feedback 2026-11-13). Within each section the row (Chest, Back, Thighs, Calves …) trained least recently comes first, so rows rotate; inside that row a started group is finished first, else grid order. Tapping still changes a pick.
- How-to animations (App HQ, 2026-11-14): exercises with a drawing get a **How to** button on the workout screen that opens a sheet with the looping figure and 2–3 form tips (`OMM/HowTo`). Reduce Motion shows the start and end poses still. `-screenshots howto` opens the first one.
- Stretch tab (from App HQ feedback, 2026-11-13): a real bottom tab replaces "Just Stretch" on the home screen. It builds a routine from what was trained today and yesterday, saves your own routines with adjustable holds, and includes yoga poses with simple pictures.

## How this repo is worked on

- Code is edited on the user's Windows PC, which has no Swift compiler.
- Every push to `main` runs `.github/workflows/build.yml` on a GitHub cloud Mac. It runs `swift test` for the package and does an unsigned Simulator build of the app. Read results with `gh run list`, then `gh run download <run id> -n report-OMM`. The report's `errors.txt` has one line per error, with repo-relative paths.
- Each report also holds `screens/` (App Store-size Simulator screenshots: the app is launched with `-screenshots <screen>`, which opens one screen with sample data, see `OMM/Support/Screenshots.swift`), `app-log.txt`, and any crash reports. Look at the screenshots after UI changes.
- TestFlight uploads run in the cloud too: push a tag `testflight-OMM-<n>` and `.github/workflows/testflight.yml` signs and uploads (logs in the `testflight-logs-OMM` artifact). It needs the four signing secrets, the same as the say-it-back repo. `./scripts/ship.sh OMM` on the user's Mac is only a fallback.
